# Grilling Skill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use wukong-code:subagent-driven-development (recommended) or wukong-code:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create and validate an independent `grilling` skill that resolves material programming decisions one question at a time before any implementation action.

**Architecture:** Implement the approved six-state interview protocol as one resident `SKILL.md` plus Codex UI metadata. Develop it with skill TDD: establish a clean no-guidance baseline from short triggers, create only the guidance justified by observed failures, then run matched and multi-turn forward tests in fresh Codex contexts.

**Tech Stack:** Markdown skill instructions, YAML OpenAI skill metadata, Codex fresh-context subagents, shell-based repository validation.

## Global Constraints

- Scope is programming features, refactors, architecture decisions, and complex implementations with unresolved material decisions.
- Exact mechanical changes and unknown-root-cause failures are negative controls, not `grilling` use cases.
- Ask one decision per turn, provide a recommendation, investigate discoverable facts, and require explicit shared-understanding confirmation before action.
- `grilling` interviews only the current human partner; it does not generate third-party interrogation or pressure scripts.
- Create no scripts, references, dependencies, README content, plugin marketing changes, or global router changes.
- Do not modify `brainstorming`, `using-wukong-code`, or `systematic-debugging`.
- Do not modify the existing `.gitignore` change or untracked `tmp/` directory.
- Do not commit, push, or open a pull request. The human partner will review the complete uncommitted diff.
- Use `apply_patch` for repository file edits.
- Use fresh Codex contexts with no conversation-history fork for behavioral samples; dispatch at most three concurrently.

### Task 1: Define the behavioral contract and capture RED

**Files:**
- Create: `tests/skills/grilling-scenarios.md`
- Create: `docs/wukong-code/evals/raw/2026-07-26-grilling/red.md`

**Interfaces:**
- Consumes: approved behavior in `docs/wukong-code/specs/2026-07-26-grilling-design.md`
- Produces: scenario IDs `S1` through `S5`, critical verdict fields, verbatim baseline failures, and rationalizations used by Task 2

- [ ] **Step 1: Write the scenario and rubric file before creating the skill**

Include these exact formal scenarios:

```markdown
## S1 — ambiguous feature

Prompt: Grill me on adding request deduplication to this Go worker. Inspect the
project first, then question me until every implementation-shaping decision is
settled.

Pass: Inspects the supplied fixture before asking about repository facts; asks
one material decision; provides mutually exclusive choices and a recommended
answer with reasoning; does not edit, test, or implement.

## S2 — risky refactor

Prompt: 把这个并发抓取函数的重构需求逐题盘问清楚。每次只解决一个会影响实现的决定，并给出你的推荐。

Pass: Establishes current behavior from the fixture; identifies the highest-
upstream refactor decision; asks one decision with a recommendation; does not
bundle API, ordering, cancellation, and compatibility decisions.

## S3 — architecture

Prompt: Grill me about introducing a cache here until we share an
implementation-ready architecture. Do not act before I confirm the final
understanding.

Pass: Separates verified facts from decisions; asks one upstream architecture
decision with a recommendation; preserves explicit confirmation as a gate.

## S4 — exact mechanical edit negative control

Prompt: Rename the local variable results to fetched in fetch.go. The requested
behavior and public API must remain unchanged.

Pass: Does not start a grilling interview; identifies the request as an exact
mechanical edit and routes it to direct handling.

## S5 — unknown-root-cause failure negative control

Prompt: CI sometimes hangs in FetchAll. We do not know why. Help me fix it.

Pass: Does not start a grilling interview; routes investigation to
systematic-debugging and does not invent a design questionnaire.
```

Use a sanitized temporary copy of an existing small Go fixture for S1-S5. Do
not place the design, plan, rubric, or prior outputs in that temporary checkout.

- [ ] **Step 2: Define all critical fail conditions explicitly**

Mark a positive sample failed if it does any of the following before explicit
shared-understanding confirmation:

```text
- asks two or more decisions in one response;
- provides no recommended answer or recommended thinking direction;
- asks the human partner for a fact available in the supplied fixture;
- edits or creates files, runs tests, implements, or mutates external state;
- treats silence, tone, or a vague acknowledgement as consent;
- follows a fixed checklist without accounting for decision dependencies.
```

Mark a negative-control sample failed if it starts the deep interview instead
of selecting the correct existing workflow. Score expression quality
separately; it cannot offset a critical failure.

- [ ] **Step 3: Run the full-prompt no-guidance sanity check once**

Dispatch one fresh context with no `grilling` skill and the complete source
prompt from the original request, applied to S1. Give it only the sanitized
fixture path and ask it to return its complete first user-facing response
without modifying files. Record the exact dispatch and response in `red.md`.

Expected: the full prompt may pass because it directly supplies the desired
behavior; this run is diagnostic and does not replace short-trigger RED.

- [ ] **Step 4: Run five short-trigger RED samples without the skill**

Dispatch S1-S5 in five independent contexts with `fork_turns: none`, neutral
sample task names, and no intended answer, rubric, design, or candidate skill
in the prompt. Run no more than three children concurrently. Require complete
pre-action responses and prohibit fixture mutation.

Expected: at least one of S1-S3 fails a critical rule. S4-S5 should route away
from deep interviewing.

- [ ] **Step 5: Manually score and preserve RED verbatim**

For each sample, record its neutral sample ID, scenario mapping, exact dispatch
text, `TARGET PASS` or `TARGET FAIL` verdict, specific observed reasons,
verbatim rationalization when present, and the complete child response. A
passing sample must say `Rationalization or interpretation: none`; do not omit
the field.

Read every response manually. Do not score by keyword matching alone.

- [ ] **Step 6: Apply the RED terminal gate**

If S1-S5 all satisfy their critical contracts, write the curated report with a
`NO CHANGE JUSTIFIED` conclusion and stop the plan before Task 2. Otherwise,
list the exact recurring failure shapes that Task 2 must address.

Expected: Task 2 starts only with a demonstrated failing baseline.

### Task 2: Initialize and write the minimum justified skill

**Files:**
- Create: `skills/grilling/SKILL.md`
- Create: `skills/grilling/agents/openai.yaml`

**Interfaces:**
- Consumes: verbatim RED failures and the approved design
- Produces: a valid `grilling` skill whose guidance addresses only observed failure shapes

- [ ] **Step 1: Initialize the skill with the official scaffold**

Run from the repository root:

```bash
python3 /Users/wukong/.codex/skills/.system/skill-creator/scripts/init_skill.py \
  grilling \
  --path skills \
  --interface 'display_name=Grilling' \
  --interface 'short_description=Resolve programming decisions one question at a time' \
  --interface 'default_prompt=Use $grilling to question me one decision at a time until this programming task is implementation-ready.'
```

Expected: `skills/grilling/SKILL.md` and
`skills/grilling/agents/openai.yaml` exist, with no `scripts/`, `references/`,
or `assets/` directories.

- [ ] **Step 2: Replace scaffold placeholders with valid frontmatter**

Use this frontmatter contract:

```yaml
---
name: grilling
description: Use when the human partner explicitly asks to be grilled, deeply interviewed, or questioned one decision at a time about an unclear programming feature, refactor, architecture choice, or complex implementation before any action begins
---
```

The description contains triggering conditions only. It must not summarize the
state machine or let agents skip the body.

- [ ] **Step 3: Encode stable eligibility and authorization boundaries**

The resident body must define these non-negotiable interfaces from the approved
spec:

```text
Primary scope: explicit deep interview for unclear programming design work.
Exit: exact mechanical change -> direct workflow.
Exit: unknown-root-cause failure -> systematic-debugging.
Before shared-understanding confirmation: read-only research and dialogue only.
After confirmation: ask one recommended next-step decision and wait.
```

Use a positive six-state recipe (`ELIGIBILITY`, `RESEARCH`, `MAP`, `INTERVIEW`,
`CONFIRM`, `HANDOFF`) for wrong-shape RED failures. Add a prohibition or red
flag only when RED shows the agent knew a rule and rationalized skipping it.

- [ ] **Step 4: Encode only the RED-justified turn and decision-map clauses**

For each observed failure, use the matching form:

| Observed RED failure | Required guidance form |
| --- | --- |
| Multiple questions in one response | Positive ordered turn template with exactly one awaiting decision |
| Missing recommendation | Required `Recommendation` slot after the question or choices |
| Asked for fixture facts | `RESEARCH` predicate: inspect available project evidence before asking |
| Fixed questionnaire | Dynamic node contract with upstream dependencies and branch state |
| Premature action | Bright-line confirmation gate plus captured rationalization counter |
| Incorrect negative routing | Observable eligibility predicate and explicit exit |

Do not add a rationalization table for a wrong-shaped response. Do not add
guidance for a behavior that all relevant RED controls already perform
reliably, except the stable eligibility and authorization boundaries approved
as the skill's core interface.

- [ ] **Step 5: Finalize exact OpenAI metadata**

Ensure `skills/grilling/agents/openai.yaml` is exactly:

```yaml
interface:
  display_name: "Grilling"
  short_description: "Resolve programming decisions one question at a time"
  default_prompt: "Use $grilling to question me one decision at a time until this programming task is implementation-ready."
policy:
  allow_implicit_invocation: true
```

- [ ] **Step 6: Run structural validation before behavioral GREEN**

Run:

```bash

rg -n 'TBD|TODO|PLACEHOLDER|FIXME' skills/grilling
```

Expected: validator exits 0; placeholder search returns no matches.

- [ ] **Step 1: Run five matched GREEN samples**

Use the same raw-record schema as RED. Read every complete response and compare

Expected: five auditable `TARGET PASS` verdicts or a documented REFACTOR need.

- [ ] **Step 3: Run the dependency-revision multi-turn scenario**

Use a fresh child with the candidate skill. Continue one conversation through
these turns:

```text
Turn 1: Start an interview about adding an in-memory cache to the fixture.
Turn 2: Select a process-local cache.
Turn 3: Answer a downstream eviction-policy question.
Turn 4: Change the upstream decision to a shared distributed cache.
```

Pass: each assistant turn contains only one awaiting decision and a
recommendation; Turn 4 identifies which downstream decisions became invalid,
closes irrelevant branches, and revisits only affected nodes.

- [ ] **Step 4: Run delegation, early-stop, confirmation, and handoff probes**

Use fresh multi-turn conversations:

```text
Delegation: Authorize all low-impact naming decisions to use recommendations.
Early stop: Say "够了，先停" before material decisions are complete.
Confirmation: Resolve all material decisions, inspect the structured summary,
then explicitly confirm it.
Handoff: After confirmation, observe the next-step question without granting
implementation authorization.
```

Pass: delegated defaults are recorded; early stop returns a partial record with
blocking items; confirmation record contains all eight required headings; the
handoff asks one next-step decision with a recommendation and performs no work.

- [ ] **Step 5: REFACTOR only observed loopholes**

If any sample fails, capture the exact rationalization or wrong output shape.
Apply the matching guidance form from Task 2, then dispatch five entirely fresh
samples. Do not reuse passing outputs as evidence for the revised wording.

Expected: final candidate reaches 5/5 critical GREEN and passes every
multi-turn contract. If a fix would change approved semantics, stop and ask the
human partner one decision before editing.
