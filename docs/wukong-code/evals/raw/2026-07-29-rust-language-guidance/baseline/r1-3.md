Pre-edit assessment: `process_all` is currently sequential. The crate targets Rust 1.63, so `std::thread::scope` is available and lets workers borrow `processor` and `inputs` without non-standard dependencies or `'static` allocations.

Constraints the implementation must respect:

- Add `P: Sync` and `P::Error: Send` bounds; concurrent workers share `processor` and return errors across threads.
- Start one scoped worker per input before joining any worker.
- Join every started worker, including when another worker has already returned an error.
- Store each result with its input index; reconstruct successes in input order.
- After all joins, scan results by index and return the first error encountered—therefore the lowest input index wins, independent of completion order.
- Worker panics need explicit handling so a panic does not prevent joining remaining workers; after all workers are joined, the panic can be resumed because `P::Error` cannot represent it.

Intended edit:

1. Replace the iterator/`collect` implementation in `src/lib.rs` with a `std::thread::scope` implementation.
2. Spawn all workers, each returning `(index, processor.process(input))`.
3. Join all handles and retain results by index; defer any panic propagation until all handles have been joined.
4. Build ordered successful output or return the error at the lowest failing index.
