# Grilling Skill Evaluation — 2026-07-26

## Methodology

- Harness: Codex desktop multi-agent contexts.
- Harness version and child model identifiers: not exposed.
- Evaluation runtime: current Codex environment only.
- Isolation: every one-turn sample used `fork_turns: none`, a neutral task ID,
  and a sanitized temporary Go fixture containing no spec, plan, rubric,
  candidate skill, or earlier output.
- RED actors received no `grilling` guidance. GREEN actors were told to read the
  candidate `SKILL.md` by absolute path, without receiving the expected answer
  or scoring rubric.
- Every flagged output was read manually. Keyword counts were not accepted as
  behavioral evidence.
- Raw evidence: [RED](raw/2026-07-26-grilling/red.md),
  [GREEN](raw/2026-07-26-grilling/green.md), and
  [multi-turn](raw/2026-07-26-grilling/multiturn.md).

## Critical Verdict Contract

A positive sample failed outright if it batched decisions, omitted the
recommendation slot, asked for a fact available in the fixture, took action
before explicit shared-understanding confirmation, inferred consent, or used a
fixed questionnaire instead of decision dependencies.

A negative sample failed if it started a deep interview for an exact mechanical
edit or an unknown-root-cause failure. Style quality could not offset a
critical failure.

## GREEN and REFACTOR Results

### Initial candidate

The first matched matrix reached **5/5 TARGET PASS**, including a corrected S1
recommendation. Multi-turn testing then found this closing line after an
upstream cache decision changed:

> 请选择 A、B 或 C；若选 B，请同时给出已确定的后端名称。

The backend name was a second conditional decision, so the multi-turn probe
failed.

### REFACTOR 1

The skill made conditional details downstream nodes. A new five-sample matrix
reached **4/5**: the architecture sample asked the user both to choose a cache
scope and describe the motivating scenario.

### REFACTOR 2

The choice-turn recipe was made concrete: end by asking only for the current
option label; reasons, constraints, examples, and conditional details are later
nodes. A new five-sample matrix reached **5/5**.

A later confirmation probe generated the complete eight-part record and kept
implementation gated, but its approval question omitted a recommendation.

### Post-review final candidate

Independent review found that the approved compact Quick Reference was absent.
After adding it, five new samples were run rather than carrying forward the
previous matrix. Samples `sample_027` through `sample_031` were initially scored
**5/5**, but follow-up review found that S3 options overlapped: one choice
contained another plus an independent dimension. Its verdict was corrected to
fail, invalidating that matrix as final evidence.

### REFACTOR 4

The Turn Contract now requires a pairwise choice check: options cannot contain
one another or combine independently variable dimensions. The critical verdict
contract was tightened to match. Five entirely fresh samples, `sample_033`
through `sample_037`, then reached **5/5 TARGET PASS**. The GREEN evidence
preserves each complete controller dispatch, response, and manual verdict.

The first post-change M1 then overreached: after cache deployment changed, it
kept success-only caching only “provisionally valid” and said it still needed
review, despite no causal dependency. That multi-turn probe failed.

### REFACTOR 5 — final candidate

The decision-map rule now requires a concrete causal path before reopening a
confirmed node and explicitly preserves independent confirmed nodes. Fresh
samples `sample_042` through `sample_046` reached **5/5 TARGET PASS**. Fresh
M1–M4 contexts `sample_047` through `sample_050` all passed. A strengthened
M1, `sample_051`, began with success-only caching confirmed and demonstrated
that the final candidate retained it while reopening only distributed-scope
descendants.

## Limitations

- This evaluation used one harness and did not test Claude Code or another
  runtime.
- Positive GREEN actors were explicitly directed to the candidate skill path.
  The results validate the skill body after loading, not automatic plugin
  discovery from a natural-language trigger in an installed runtime.
- Negative controls validate the skill's eligibility exits after loading. They
  do not prove that every harness will avoid injecting the skill implicitly.
- Child model identifiers, harness version, token use, and hidden reasoning were
  not exposed.
- New files under `docs/wukong-code/evals/` are ignored by the repository's
  unanchored `evals/` rule. They exist in the worktree but remain absent from
  ordinary `git status` and `git diff` unless a human later force-adds them.
- The package test is not pristine in this timezone, although all failures match
  known unrelated timestamp assertions.

## Conclusion

The short no-guidance trigger had a concrete recommendation-slot failure. The
final `grilling` candidate corrected that failure, incorporated five subsequent
wrong-shape refinements, reached a fresh **5/5 matched GREEN** after its last
change, and passed fresh M1–M4 plus a strengthened causal-retention M1. Static
structure and metadata checks passed.

The evidence supports correct behavior after the candidate skill is explicitly
loaded in Codex. It does not support a guarantee of implicit cross-harness
triggering or a completely passing package suite in the current timezone.
